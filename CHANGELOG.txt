## [0.0.17] - 2026-09-09

### Fix: recargas del dev server, parpadeo de tema y pérdida de la venta en curso

#### Corregido
- **Parpadeo tipo cambio de tema (FOUC) en cada carga**: la clase `dark` se aplicaba
  dentro de un `useEffect` (después del primer pintado) con transición de colores
  activa. Se agregó un script inline en `index.html` que aplica el tema guardado
  (`app_theme`), `color-scheme` y el color de fondo base **antes del primer frame**.
  Aplica tanto en dev como en el build de producción.
- **Pérdida de la venta a medio cargar al recargarse la pestaña**: `SaleFormModal` ahora
  autoguarda un borrador en `localStorage` (`app_sale_draft_v1`, debounce 600 ms) y lo
  restaura al reabrir el modal, mostrando un aviso con la fecha y un botón
  "Descartar borrador". El borrador se limpia al guardar o cerrar explícitamente
  (X / Cancelar) y hay aviso `beforeunload` si se intenta salir con cambios sin guardar.
- **Auto-bloqueo por inactividad al volver de otra ventana**: el temporizador ignoraba
  `document.hidden`. Ahora se pausa con la pestaña oculta, se reinicia al volver
  (`visibilitychange`), y también se refresca en `focus`; deja de aparecer la pantalla
  de PIN encima del modal al regresar.

#### Añadido
- **Modos de ejecución sin recargas**:
  - `npm run dev:stable` → dev server con `DISABLE_HMR=true` (sin HMR ni watcher: elimina
    las recargas por cambios de archivos).
  - `npm run stable` → `npm run build && node server.js`: sirve el build de producción,
    **sin cliente de Vite** ⇒ cero recargas automáticas (recomendado para operar).
  - Dependencia `cross-env` para scripts multiplataforma.

#### Notas técnicas (hallazgo)
- La recarga de pestaña en desarrollo es del propio cliente de Vite
  (`location.reload()` al reconectar el WebSocket tras perderlo, `client.mjs:962-969`).
  Se verificó que `server.hmr: false` **no** evita que el cliente se inyecte y se conecte
  (mismo `wsToken` servido en ambos modos), por lo que ese flag reduce las recargas por
  archivos, pero no las de reconexión: para eliminarlas hay que servir el build
  (`npm run stable`).

#### Calidad
- `npm run lint`: 0 errores / 2 warnings (preexistentes en `SaleLocationMap`).
- Tests: **8 suites / 74 tests** OK. Build de producción OK.

## [0.0.16] - 2026-09-09

### Fix: React Hooks en modales legacy (reglas de hooks cumplidas en todo el código)

#### Corregido
- **6 modales declaraban hooks DESPUÉS de un `return null` temprano** (`if (!isOpen)`),
  violando las Reglas de Hooks de React (orden condicional → riesgo de crash
  "Rendered more hooks than during the previous render" al cerrar/reabrir):
  `AnalyticsModal`, `CustomerDirectoryModal`, `ExportModal`, `ImportModal`,
  `SaleFormModal` y `WooCommerceModal`.
- Refactor con patrón **wrapper + inner component**: el export público conserva el
  guard `isOpen` y monta un componente interno (`XModalInner`) que contiene TODOS los
  hooks. Así los hooks corren únicamente cuando el modal está abierto y con los props
  correctos (los inicializadores de estado se ejecutan al abrir, sin estados obsoletos).
- `eslint.config.js`: eliminado el override que degradaba `react-hooks/rules-of-hooks`
  a warning en esos 6 archivos — la regla vuelve a ser **error en todo el código**.

#### Calidad
- `npm run lint` (tsc + eslint): **0 errores | 2 warnings** (solo `exhaustive-deps`
  preexistentes de `SaleLocationMap`).
- Tests: **8 suites / 74 tests** OK. Build de producción OK.

## [0.0.11] - 2026-09-09

### Endurecimiento de Seguridad del PIN (H1)

#### Corregido
- **El PIN ya nunca se persiste en texto plano**: al guardar la configuración, un PIN
  legacy en claro (ej. `"1234"` de instalaciones previas o del seed inicial) se migra
  automáticamente a su hash (SHA-256 / cyrb53) aunque no se escriba un PIN nuevo.
- **Auth Gate real al inicio de sesión**: si "Habilitar PIN" está activo, la aplicación
  arranca bloqueada pidiendo el PIN (antes el control solo actuaba con el bloqueo manual
  o por inactividad, por lo que un alta de sesión quedaba sin protección).

#### Añadido (características)
- **Bloqueo progresivo ante intentos fallidos** (`AuthModal`): 3 intentos fallidos
  bloquean el login por 5 segundos, 5 por 30 segundos y 7 o más por 60 segundos.
  El contador persiste en `sessionStorage` (sobrevive recargas de pestaña) y se
  registra en el log de auditoría.
- **Validación al habilitar la seguridad** (`ConfigModal`): no se permite ACTIVAR el
  control de acceso dejando el PIN predeterminado `"1234"` — se exige fijar un PIN
  nuevo antes de habilitar. Aviso visual ámbar cuando el PIN en uso sigue siendo el
  predeterminado.

## [0.0.10] - 2026-09-09

### Servidor de Producción Standalone (`server.js`) y Capa de API Compartida

#### Añadido (características)
- **Servidor de producción Node.js (`server.js`)**:
  - Sirve el build estático de Vite (`dist/`) con tipos MIME, protección contra path traversal y fallback SPA para navegación directa.
  - Monta la misma superficie de API que el dev server: `/api/backup` (POST), `/api/backup/list` (GET), `/api/backup/restore` (POST) y `/api/tracking/andreani/bulk` + `/api/tracking/andreani/:nro` (GET).
  - De este modo los **backups en disco y el seguimiento de envíos Andreani funcionan también en producción**, no solo durante `npm run dev`.
  - Configurable por entorno: `PORT` (3000), `HOST` (0.0.0.0) y `DIST_DIR` (./dist).
- **Capa de API compartida (`api-handlers.js`)**:
  - Extrae toda la lógica de handlers (backups + Andreani) que antes vivía dentro del middleware de `vite.config.ts`.
  - Se monta en ambos contextos —middleware del dev server y `server.js`— eliminando la duplicación de código.
  - Contrato estable: `handleApiRequest(req, res, options)` → `Promise<boolean>` (`true` si la petición era `/api/*` y ya fue respondida, incluidos los 404 de rutas desconocidas).
  - Mejoras menores de robustez: 400 para JSON inválido o cuerpo vacío en endpoints que esperan JSON, y 404 explícito para rutas `/api/*` desconocidas (antes la conexión podía quedar sin respuesta).

#### Cambiado
- `npm run dev` usa el mismo módulo `api-handlers.js` vía middleware de Vite (comportamiento idéntico al anterior).
- Script `clean` ya no elimina `server.js` (ahora es fuente versionada); solo limpia `dist/`.
- Nuevo script `npm start` → `node server.js` para correr el sistema en producción.

  - Auto-consulta en segundo plano al visualizar o cambiar de página para todas las ventas con envío de Andreani no terminales.

  - El selector dropdown de la grilla refleja y actualiza reactivamente `sale.estadoEnvio` al recibir datos frescos de Andreani y permite modificación manual directa en cualquier momento.

- **Pipeline Automatizado de CI/CD en GitHub Actions (`.github/workflows/ci.yml`)**:
  - Flujo de integración continua para pull requests y commits en `master`/`main` que ejecuta: instalación con `npm ci`, verificación de tipos (`npx tsc --noEmit`), suite de 60 tests (`npm test`) y build de producción (`npm run build`).

#### Seguridad y Blindaje de Datos
- **Protección contra Fuga de Backups y Logs (`.gitignore`)**:
  - Exclusión estricta de la carpeta `backups/` para evitar que snapshots con datos de clientes o claves API se suban accidentalmente a Git o CI/CD.
  - Exclusión de `andreani-shipping/`, `*.log` y directorios internos de trabajo.
- **Sanitización contra Inyección de Fórmulas CSV (`formatters.ts`)**:
  - Sanitización en `exportSalesToCSV` de caracteres disparadores (`=`, `+`, `-`, `@`, `\t`, `\r`) anteponiendo comilla simple `'` para prevenir ejecución maliciosa en hojas de cálculo.
- **Protección contra Path Traversal (`vite.config.ts`)**:
  - Validación de `path.basename` y restricción a archivos `.json` con prefijo `backup-` en el endpoint `/api/backup/restore`.
- **Validación Robusta de PIN (`security.ts`)**:
  - Compatibilidad ampliada en `isHashedPin` para admitir tanto hashes SHA-256 (64 hex) como hashes de respaldo syncDigest (16 hex).

### Configuración Personalizada de Envíos

#### Añadido (características)
- **Configurador de Envíos**: Añadidas las secciones "Métodos de Envío" y "Estados de Envío" en el configurador general (`ConfigModal.tsx`), con soporte CRUD (añadir, editar, eliminar) dinámico para personalizar las opciones operativas de logística del comercio.
- **Selectores Dinámicos**: Los menús desplegables del registro de ventas (`SaleFormModal.tsx`), de edición directa de celdas y de filtros de la barra de herramientas (`SpreadsheetGrid.tsx`) leen dinámicamente las opciones desde la configuración guardada del sistema.
- **Retrocompatibilidad**: Auto-migración al iniciar la aplicación para fusionar los nuevos arrays de configuración con los valores por defecto si se detectan configuraciones previas en el navegador.

## [0.0.4] - 2026-08-13

### Sistema de Copias de Seguridad y Mejoras en Paginación

#### Añadido (características)
- **Copias de Seguridad Automáticas**: Implementación de un sistema de doble respaldo de datos (ventas, catálogo, clientes, configuración). Guarda copias de seguridad tanto en archivos físicos `.json` en disco (carpeta `./backups/` mediante backend de Vite) como de forma redundante en el navegador (`IndexedDB`).
- **Configurador de Backups**: Nueva pestaña en `ConfigModal.tsx` para habilitar el guardado automático, seleccionar periodicidades (arranque, diario, semanal, cada 20 o 50 ventas), generar copias manuales en el acto y ver una tabla interactiva con la fecha, origen y tamaño de cada copia para restaurarla con un clic.
- **Banner de Recuperación por Pérdida de Datos**: Banner de alerta parpadeante en la cabecera que se despliega si `localStorage` se encuentra vacío pero existen copias en disco o IndexedDB, facilitando la restauración inmediata de la base de datos.
- **Mostrar Todo en Planilla**: Checkbox "Mostrar todos" incorporado en la barra de controles de paginación de `SpreadsheetGrid.tsx`. Al activarlo, muestra todas las filas en una sola página y deshabilita el selector de cantidad de registros.

## [0.0.3] - 2026-08-08

### Mejoras en panel principal, exportación PDF y personalización de KPIs

#### Corregido (bugs)
- **Filtrado por Mes en Planilla**: Corregido el bug por el cual la planilla interactiva (`SpreadsheetGrid.tsx`) no filtraba los registros según el mes seleccionado en la cabecera, mostrando todas las ventas de la base de datos (por ejemplo, registros del 2020 al estar seleccionado Agosto 2026).
- **Desalineación de Columnas**: Corregida la desalineación en el panel principal de ventas (`SpreadsheetGrid.tsx`), alineando correctamente las cabeceras con los datos en el orden de: Canal -> Met. Pago -> Método de Envío -> Nº de Envío.
- **Márgenes en Descarga PDF**: Corregido el desplazamiento y recorte lateral en los PDFs generados (`BudgetModal.tsx`, `RemitoModal.tsx`, `index.css`). Se aisló el área de renderizado en `position: fixed` a coordenadas `(0,0)` para evitar la influencia del viewport o scroll, y se fijó el ancho de exportación en `794px` en `html-to-image`.
- **Alineación Vertical de Presupuestos**: Se cambió la alineación vertical del PDF de Presupuesto a la parte superior de la hoja A4 (`y = margin`) en lugar de centrado vertical.
- **Redundancia de Enlaces Andreani**: Removido el enlace redundante de la columna "Método de Envío" y unificado dentro del número de seguimiento en la columna "Nº de Envío".

#### Añadido (características)
- **Paginación en Planilla**: Se incorporó un sistema de paginación interactivo con controles de navegación (Página anterior/siguiente) y un selector dinámico para configurar el límite de registros por página (de 10 en 10, desde 20 a 100).
- **Filtro "Mostrar Todos"**: Añadido checkbox "Mostrar todos" al lado del selector de mes en `KpiSummary.tsx`. Permite alternar entre visualizar únicamente las ventas del mes seleccionado o el historial completo acumulado (el cual deshabilita temporalmente el selector de fecha y recalculó los KPIs a totales históricos).
- **KPIs Personalizables**: Se agregó un configurador de indicadores (ícono de engranaje ⚙) en `KpiSummary.tsx` que permite activar/desactivar individualmente cada tarjeta métrica (Acumulado Mensual, Ticket Prom., etc.), persistiendo la selección del usuario en `localStorage` y auto-ajustando dinámicamente el layout de columnas.
- **Título de la Pestaña**: Actualizado el título del sitio en `index.html` a "SalesHub".

## [0.0.2] - 2026-08-03

### Mejoras y fixes de robustez, seguridad y deuda técnica

#### Corregido (bugs)

- **`numberToWords.ts`**: `novecentos` → `novecientos` (error ortográfico en centenas,
  no cubierto por tests). Se agregó cobertura para 900 y 950.
- **`ImportModal`**: el parsing de montos argentinos (`$ 1.250,00`) perdía los miles
  (daba `1.25`). Nuevo helper puro `parseAmountString` en `formatters.ts` que maneja
  separadores de miles y decimales en formatos ARS/US, con tests.
- **IDs de venta colisionables**: `Math.random()` en `App.tsx` y `SaleFormModal` se
  reemplazó por `generateSaleId`, secuencial sin colisiones (`V-2026-00001`...).
- **CSV**: `exportSalesToCSV` ahora escapa correctamente todos los campos (comas,
  comillas y saltos de línea) en lugar de solo productos/notas.
- **AuthGate (RBAC)**: antes se podía entrar como OPERADOR sin ingresar ningún PIN;
  ahora ambos perfiles requieren verificación. El botón muestra estado "Verificando...".

#### Seguridad

- **WooCommerce API**: se eliminaron los proxies CORS de terceros (`corsproxy.io`,
  `api.allorigins.win`) que recibían `consumer_key`/`consumer_secret` en la URL.
  Ahora la sincronización usa fetch directo; si el navegador bloquea por CORS se
  requiere un proxy reverso same-origin (Nginx) según el README.
- **PIN persistido en texto plano**: `ConfigModal`/`AuthModal` ahora almacenan y
  verifican un hash del PIN (`src/utils/security.ts`, SHA-256 con fallback síncrono).
  Se conserva retrocompatibilidad con PINs legacy.
- `transformWooCustomer` ya no fabrica DNI/teléfono/dirección falsos en clientes
  reales importados de WooCommerce.

#### Deuda técnica

- Dependencias muertas eliminadas: `express`, `@types/express`, `dotenv`,
  `@google/genai` y `html2pdf.js` (se importaba `jspdf` directo). Se agregó `jspdf`
  como dependencia directa.
- `vite.config.ts`: corregido comentario con encoding corrupto.
- `package.json` renombrado a `saleshub` v1.0.0; Header ahora muestra la marca de la
  empresa configurada en vez de un nombre genérico.
- `App.tsx`: handlers de ventas/presupuestos/catálogo migrados a functional setState
  (evita stale closures).
- `alert()` reemplazado por feedback inline en `ExportModal` e `ImportModal`.

#### Calidad

- 48 tests unitarios en 6 suites (antes 38), lint y build de producción OK.

## [0.0.1] - 2026-08-01

### Commit inicial - Lanzamiento del Sistema de Gestión Comercial

Primera versión estable del sistema de gestión comercial omnicanal como herramienta
de front-office complementaria al ERP de la firma. Registro de ventas,
presupuestos AFIP, remitos y despacho en el punto de venta.

#### Añadido (características)

- **Planilla interactiva de ventas** (`SpreadsheetGrid`): edición inline, filtros por
  mes de emisión y canal (Local, WhatsApp, WooCommerce, MercadoLibre), acceso a remitos.
- **Gestor de presupuestos AFIP** (`BudgetModal`): numeración correlativa PRES-XXXX,
  IVA 21%, percepciones de Ingresos Brutos, bonificaciones, buscador autocompletable de
  catálogo/clientes, impresión PDF/A4 y **conversión a venta en 1 clic**.
- **Envíos omnicanal** (`SendBudgetModal` + `budgetDelivery`): WhatsApp `wa.me` con
  normalización de numeración argentina (+54 9) y plantilla de correo `mailto:`.
- **Remitos de transporte** (`RemitoModal`): Remito X - documento no válido como factura,
  con datos de flete, dirección de entrega y firma de conformidad.
- **Sincronizador WooCommerce** (`WooCommerceModal` + `wooCommerceApi`): sync bidireccional
  de catálogo (precios, stock, SKUs) y clientes, con paginación y CORS proxy.
- **Panel de analítica** (`AnalyticsModal` + `KpiSummary`): facturación mensual, ticket
  promedio, ventas por canal y gráficos Recharts.
- **Directorio de clientes** (`CustomerDirectoryModal`): historial de compras, totales y
  alta automática al registrar ventas.
- **Import/Export** (`ImportModal` / `ExportModal`): CSV y JSON de ventas y datos.
- **Auditoría completa** (`SystemLogsModal` + `logger`): niveles INFO/WARN/ERROR/SYNC/API/
  SALE/BUDGET, filtros dinámicos y exportación JSON/CSV.
- **Seguridad** (`AuthModal`): Auth Gate con PIN, perfiles RBAC (Operador/Administrador)
  y auto-bloqueo por inactividad configurable (5-60 min).
- **Persistencia local**: caché completa en `localStorage` (ventas, catálogo, presupuestos,
  clientes, config, tema) sin dependencia de servidor.

#### Arquitectura

- Modular Clean Architecture basada en SOLID; `App.tsx` como orquestador de estado.
- Strict Typing Layer en `src/types.ts` (Sale, Budget, Customer, CatalogProduct, LogEntry...).
- Helpers funcionales puros y 100% testeados (`numberToWords`, `formatters`, `budgetDelivery`).
- Fail-safe & graceful degradation en la integración WooCommerce (simulador de catálogo
  ante fallos de red).

#### Calidad

- 38 tests unitarios en 6 suites Vitest, cobertura promedio >91%.
- `npm run lint` (tsc --noEmit) sin errores.
- `npm run build` (Vite producción) correcto.

#### Documentación

- README ampliado con visión de complemento al ERP, modelo de datos y flujo de integración
  front-office -> ERP.

### Notas de mantenimiento

- `graphify-out/` (salida generada por la herramienta de análisis de grafos) está excluido
  del repositorio vía `.gitignore`.
- La sincronización WooCommerce depende de un proxy reverso same-origin (Nginx) para
  operar desde el navegador; los proxies CORS de terceros fueron eliminados por seguridad.
- `bun.lock` queda obsoleto (generado sin `bun` en el entorno); regenerar con `bun install`
  si se usa Bun, o ignorar y usar `package-lock.json` (npm).
